# API 실험 기능 추가

‘나의 실험’에서 조건 설정, 충돌 확인, 비교안 이력, OpenAI API 실행, 응답 분석, 관련 차시 복습 안내를 사용할 수 있습니다. API 키는 서버 환경변수로 설정하며 자세한 방법은 `API_SETUP.md`를 참고하세요. 기존 학습 기능은 그대로 유지됩니다.

# 프롬프트 실험실 · precision-1

## 실행

BRB 폴더의 **프롬프트_실험실.html**을 Chrome 또는 Edge에서 엽니다. 인터넷 연결이나 설치, 로그인, API 키가 필요 없습니다. 기존 탭을 열어 두었다면 새로고침하세요. `prompt-lab/Prompt_Lab.html`은 같은 앱의 다른 복사본입니다. 파일 위치별로 브라우저 기록이 달라질 수 있으므로 평소에는 한 파일을 계속 사용하세요.

## 이번에 바꾼 핵심

- 8차시 × 약20분: 첫 판단 → 원리 → 오답별 피드백 → 직접 작성·수정 → 새 문제.
- 선택형 학습24문항, 선택지별 피드백, 첫 시도와 재시도 분리.
- 첫 초안 보존, 수정본과 세 기준의 근거 및 수정 이유 저장.
- 사전/사후/지연 평가: 회당 객관식6문항 + 직접 설계1문항. 회당10~15분 별도 예상.
- 제출 잠금, 선택지 순서 섞기, 해설 공개 시각·외부 도움·실제 지연 간격 기록.
- 직접 설계0~8점 기준, 자기검토와 외부 검토 구분, 근거와 변경 이력 보존.
- 한 단계씩 보는 화면, 진행 중 저장, 키보드 초점 이동, 작은 화면용 배치.
- 원논문의 실제 응답6쌍과 집계, 원채점/앱 보완 판정 구분 유지.

약20분은 설계 목표이며 실제 평균 시간을 측정한 결과는 아닙니다. 자유 서술은 자동 정답 판정을 하지 않습니다. 활동을 저장한 것과 학습 성취는 다릅니다.

## 권장 사용 순서

1. 처음 사용 안내의 예시를 읽습니다.
2. 학습 전 기준점이 필요하면 ‘배움 확인’에서 사전 평가를 먼저 합니다.
3. 학습 과정을 여러 날에 나누어 진행합니다. 중단해도 마지막 단계와 입력이 저장됩니다.
4. 과정을 마친 뒤 사후 평가를 합니다. 가능하면 해설 공개 전에3~7일 뒤 지연 평가를 합니다.
5. 직접 설계 답안·채점표를 내보내 다른 검토자에게 평가받고 점수와 근거를 기록합니다.

사전 평가를 건너뛰어도 학습할 수 있습니다. 이미 이전 버전 학습 기록이 있으면 사전 점수에 학습 경험이 섞였다는 표시가 남습니다. 앱은 다른 기기나 다른 사이트에서의 학습을 자동 감지하지 못합니다.

## 저장과 복원

학습 과정 아래 ‘전체 기록 백업’으로 JSON을 받습니다. 새 과정 백업 불러오기는 precision-1 기록을 검증한 후 교체하며 현재 비교 기록과 이전 과정 기록은 그대로 둡니다. 전체 백업에는 이전 기록도 보존되지만, 이전 버전 과제를 새 과제에 자동 대응시키거나 복원하지 않습니다.

이전 `course`/`course20` 기록은 삭제하거나 새 과제의 답으로 옮기지 않았습니다. ‘학습 기록’의 삭제 버튼은 비교 사례와 원실험 틀 연습만 지우며 새 과정과 평가를 유지합니다. 저장소가 제한되면 경고하므로 브라우저를 닫기 전에 백업하세요.

평가 JSON에는 직접 작성한 답안이 포함됩니다. 개인정보를 적지 마세요. 앱은 기록을 서버로 보내지 않습니다. 앱 파일을 수정하거나 개발자 도구를 사용하는 행위까지 막는 시험 보안 도구는 아닙니다.

## 설계·검증 문서

- `LEARNING_DESIGN.md`: 논문 결과 → 목표 → 활동 → 평가의 연결, 범위와 한계.
- `VALIDATION_PROTOCOL.md`: 예비 사용성 점검, 측정 도구 검토, 읽기 비교 조건, 독립 채점, 실제 연구 절차.
- `READING_COMPARISON.html`: 같은 개념·문제·해설·원자료를 제공하는 읽기 자료. 일반 학습자는 앱을 사용하세요.
- `study-register.csv`: 실제 연구에서 사용할 빈 기록표. 참여자 결과가 들어 있지 않습니다.
- `verification.json`, `verification-learning.json`: 소프트웨어 검사 결과. 교육 효과의 증거가 아닙니다.

## 현재 검증 상태

원자료의 96개 규칙 판정 재현과 기존 기능 검사, 새 과정의 상태 전이·누락 방지·첫 시도 보존·평가 잠금·노출 표시·백업 복원·저장 실패 처리를 검사했습니다. 실제 Chrome 화면 검증은 컴퓨터 사용 도구의 현재 URL 확인 실패로 차단되어 완료하지 못했습니다. 실제 학습자와 독립 채점자 대상의 학습 효과 검증도 아직 수행하지 않았습니다.

## 소스와 재구성

소스는 `dist/`에 있습니다. `index.html`이 `data.js`, `course.js`, `learning-data.js`, `learning.js`, `app.js` 순서로 읽습니다. `course.js`는 기존 과정 자료와 이전 기록 처리 함수를 보존하고, 새 과정 화면은 `learning.js`가 구성합니다.

프로젝트 디렉터리에서:

```text
node verify.cjs
node verify-learning.cjs
node build-reading.cjs
python package.py
```

`verify.cjs`는 원자료·기존 기능 회귀검사, `verify-learning.cjs`는 현재 학습·평가 흐름 검사입니다. 브라우저를 대체하는 테스트는 아닙니다. `package.py`는 외부 의존성 없는 단일 HTML과 상위 폴더의 ZIP을 만듭니다. 루트 실행 파일 반영은 생성한 `Prompt_Lab.html`을 BRB의 `프롬프트_실험실.html`로 복사합니다.

`build_data.py`로 원자료를 다시 추출하려면 별도로 원본 `T10파일.zip`이 필요합니다. 앱 실행에는 필요 없습니다. 새 모델을 호출하지 않으며 API 키를 요구하지 않습니다.
